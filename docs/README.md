# Documentation map

To reproduce the project, start from the [main README](../README.md).
To read the results, start from the [guide for the jury](../LEGGIMI_GIURIA.md).
Paths written in backticks in the documents are relative to the repository root.
This map describes the complete repository: the ZIP for the jury excludes ideas,
archive material, the Markdown sources of the report and policy (their PDFs are included in `dist/`), the
presentation sources (for the deck, only the v5 PDF is included,
`dist/PRESENTAZIONE_PONTE_19.pdf`), the deck generator, and the team's internal materials (personal
contexts, dated updates, technical review). Of the team documents, only
`team/SCELTE_ANALITICHE.md` is included.

## Which file to edit

- Report and policy: edit the Markdown files in their respective folders, then run
  `python -m pipeline.relazione_docx` and `python -m pipeline.policy_docx` in the project environment.
- Fact sheets: edit `pipeline/schede.py` and regenerate with `python -m pipeline.schede`.
- Education reports: the three reports and the execution/validation JSON files are generated;
  the instructions and methodological documents are described in the thread README.
- Presentation: the decks are in `presentazione/`, one version per file (v1-v5), and are not
  overwritten. v4 is the version projected on September 24; v5 corrects four of its
  slides and is the version that was submitted ([changes](presentazione/MODIFICHE_PPTX_2026-09-24.md)). The generator `pipeline/presentazione_pptx.py` is not aligned with the
  current figures (the [team update](team/AGGIORNAMENTO_SAVERIO_2026-09-23.md)
  documents this): do not use it to regenerate the deck.

## Exports and submissions

`dist/` contains PDFs, HTML notebooks, and ZIP files that can be regenerated with `python -m pipeline.pdf`.
The documentation reorganization preserves this workflow and keeps DOCX files, fact sheets, and reports next to
their respective working areas. Fully separating exports into
subfolders within `dist/` is a possible later step.

A current export does not certify a past submission: preserve the originals
that were actually submitted, with their date, without reconstructing them from updated sources.
